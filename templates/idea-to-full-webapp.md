اسم المشروع الداخلي: kamel3lom

أنت الآن مهندس برمجيات Full-Stack محترف، ومصمم تجربة مستخدم UX/UI، ومهندس نظم، ومراجع جودة كود. أريد منك بناء تطبيق ويب كامل من الفكرة إلى الكود الجاهز للتشغيل والنشر، وليس مجرد مثال مبسط أو واجهة شكلية.

أولًا: بيانات المشروع

اسم التطبيق: {{APP_NAME}}
وصف الفكرة: {{IDEA_DESCRIPTION}}
المشكلة التي يحلها التطبيق: {{PROBLEM_SOLVED}}
الفئة المستهدفة: {{TARGET_AUDIENCE}}
نوع التطبيق: {{APP_TYPE}}
لغة الواجهة: {{UI_LANGUAGE}}
اتجاه الواجهة: {{DIRECTION}}
المستوى المطلوب: {{LEVEL}}
التقنيات المفضلة: {{PREFERRED_TECH}}
طريقة النشر المطلوبة: {{DEPLOYMENT_TARGET}}

ثانيًا: المطلوب منك قبل كتابة الكود

حلل الفكرة تحليلًا برمجيًا ومنتجيًا واضحًا، ثم استخرج: 1) الهدف الأساسي من التطبيق. 2) المستخدمون المحتملون وأدوارهم. 3) الصفحات الرئيسية المطلوبة. 4) الوظائف الأساسية والثانوية. 5) تدفق المستخدم User Flow. 6) بنية البيانات المناسبة. 7) الجداول أو الكيانات المطلوبة إذا احتاج التطبيق قاعدة بيانات. 8) الصلاحيات والأدوار إن وجدت. 9) نقاط القوة والضعف في الفكرة. 10) أفضل تقنية مناسبة مع تبرير مختصر.

ثالثًا: بنية التطبيق المطلوبة

صفحة رئيسية Landing Page، صفحة تسجيل الدخول/إنشاء حساب إذا احتاج مستخدمين، لوحة تحكم Dashboard، صفحات إدارة البيانات الأساسية، صفحة إعدادات، صفحة ملف المستخدم، صفحة عرض التفاصيل، صفحة إضافة/تعديل/حذف، صفحة خطأ 404، مكونات قابلة لإعادة الاستخدام Components، نظام تنقل واضح Navbar/Sidebar، تصميم Responsive للحاسوب والجوال، دعم RTL إن كانت عربية، رسائل تنبيه ونجاح وخطأ واضحة، حالات تحميل Loading States، حالات فارغة Empty States، تحقق من صحة المدخلات Form Validation.

رابعًا: متطلبات التصميم

واجهة نظيفة ومنظمة غير مزدحمة، ألوان متناسقة، Tailwind CSS أو نظام تصميم مناسب، بطاقات وأزرار احترافية، أيقونات مناسبة، تباعد بصري مريح، خطوط واضحة، تجربة سهلة للمبتدئ، تصميم قابل للتوسع، تجنّب التصميم البدائي أو المكرر، لمسة بصرية تقنية عصرية دون مبالغة. إذا كان التطبيق عربيًا: واجهة عربية فصيحة بالكامل، اتجاه RTL، تجنّب النصوص العامية أو العشوائية.

خامسًا: متطلبات الكود

كود حقيقي قابل للتشغيل، منظم في ملفات واضحة، قابل للصيانة، أسماء متغيرات ودوال مفهومة، خالٍ من التكرار، مقسم إلى Components، يحتوي معالجة أخطاء مناسبة، تعليقات مختصرة فقط عند الضرورة، قابل للنشر، لا يعتمد على ملفات غير مذكورة، لا يترك أجزاء ناقصة مثل "أضف الكود هنا"، لا يستخدم بيانات وهمية إلا إذا ذُكر بوضوح أنها تجريبية.

سادسًا: قاعدة البيانات والربط الخلفي

إذا احتاج التطبيق حفظ بيانات: اقترح قاعدة البيانات الأنسب، ثم أنشئ نموذج البيانات، الجداول أو Collections، العلاقات بينها، عمليات CRUD، واجهات API إن لزم، أمثلة بيانات تجريبية، طريقة الربط بين الواجهة والخلفية، قواعد التحقق من البيانات، اعتبارات الأمان الأساسية. إذا لم تكن هناك حاجة فعلية لـBackend، اشرح ذلك باختصار واختر بنية Frontend مناسبة.

سابعًا: الأمان والجودة

راجع: حماية المدخلات، منع الأخطاء الشائعة، عدم كشف المفاتيح السرية، تنظيم متغيرات البيئة .env، صلاحيات المستخدمين، التعامل مع أخطاء الشبكة، قابلية التوسع مستقبلًا، الأداء وسرعة التحميل، تحسين تجربة المستخدم، قابلية النشر على الاستضافة المختارة.

ثامنًا: مخرجات التسليم المطلوبة

1) ملخص تنفيذي قصير لفكرة التطبيق. 2) تحليل المتطلبات. 3) خريطة الصفحات والوظائف. 4) البنية التقنية المقترحة. 5) هيكل ملفات المشروع. 6) الكود الكامل لكل ملف. 7) تعليمات التشغيل محليًا. 8) تعليمات إنشاء ملف .env إن وُجد. 9) تعليمات النشر خطوة بخطوة. 10) قائمة تحسينات مستقبلية مقترحة. 11) اختبار سريع للتأكد من أن التطبيق يعمل. 12) مراجعة نهائية للأخطاء المحتملة.

تاسعًا: شروط صارمة

لا تكتفِ بالشرح النظري. لا تعطِ واجهة فقط دون منطق. لا تعطِ كودًا ناقصًا. لا تستخدم مكتبات كثيرة بلا ضرورة. لا تجعل التطبيق معقدًا فوق الحاجة. لا تهمل تجربة المستخدم. لا تهمل الجوال. لا تضع بيانات حساسة داخل الكود. لا تفترض معلومات جوهرية غير مذكورة؛ إذا كانت هناك معلومة ناقصة، اتخذ أفضل افتراض عملي واذكره بوضوح. لا تطلب تأكيدًا في كل خطوة؛ أنجز أفضل نسخة ممكنة مباشرة.

عاشرًا: أسلوب الإخراج

اكتب بلغة عربية فصحى واضحة عند الشرح، واكتب الكود باللغة البرمجية المناسبة. اجعل المشروع احترافيًا ومناسبًا لوضعه في GitHub، مع README واضح، وتعليمات تشغيل ونشر مفهومة للمبتدئ.

ابدأ الآن بتحليل الفكرة ثم ابنِ التطبيق كاملًا.
