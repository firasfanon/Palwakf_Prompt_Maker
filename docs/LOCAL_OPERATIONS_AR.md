# التشغيل المحلي الفعلي — Local Companion وOllama والتحقق الحقيقي

> الحالة: **BUILT_NOT_INTEGRATED** (فرع `task/gfpi-v1-operational-productization-mb1`). هذا دليل تشغيل، وليس ادعاء جاهزية إنتاج.
> كل ما في CI وفي اختبارات هذا المستودع يستخدم **بدائل اختبار** (test doubles) لخدمة النموذج؛ التشغيل الحقيقي على
> جهازك هو ما يغلق بنود `NOT_PROVEN` أدناه، وبأدلة يولّدها الأمر `probe` نفسه.

## 1. التشغيل بأمر واحد (لمستخدم غير تقني)

```bash
npm run app                                   # بلا نموذج: كل القدرات الحتمية تعمل، والاقتراحات الذكية «غير متاحة» بصراحة
npm run app -- --ollama-model qwen2.5:3b      # مع نموذج محلي (أي اسم مثبت عندك؛ لا نموذج مفروض)
```

يطبع الأمر عنوانًا واحدًا لفتحه (`http://127.0.0.1:8787/`) ورمز اقتران. افتح العنوان، ثم من تبويب **الاتصال** أدخل
الرمز فقط؛ عنوان الـ Companion مملوء تلقائيًا. اضغط Enter في الطرفية للحصول على رمز جديد في أي وقت (مثلًا بعد انتهاء
الجلسة). يتوقف بـ Ctrl+C.

ما يضمنه المشغّل:

| الضمان | كيف |
|---|---|
| loopback فقط | يستمع على `127.0.0.1`؛ غير قابل للوصول من الشبكة (مثبت باختبار S14 وبدليل OP-7) |
| لا اجتياز مسارات | قائمة بيضاء حرفية من 5 ملفات تُقرأ عند البدء؛ لا يُشتق أي مسار من الطلب |
| ضد التضمين (clickjacking) | `frame-ancestors 'none'` و`X-Frame-Options: DENY` على واجهة الاقتران |
| ضد DNS rebinding | فحص Host صارم للواجهة والـ API |
| الأسرار | المتصفح لا يستلم أي مفتاح مزوّد؛ الاستدعاءات المدفوعة **غير مصرّح بها** والميزانية الافتراضية صفر |
| طلب واحد في وقت واحد | خدمة النموذج المحلية تخدم توليدًا واحدًا؛ الطلب الثاني يُرفض `409 RUN_IN_PROGRESS` |
| إلغاء حقيقي | زر «إلغاء الطلب» يُجهض طلب المتصفح ويطلب من الـ Companion إجهاض التشغيل؛ انقطاع المتصفح يُجهضه أيضًا |
| مهلة تُلغي ولا تُكرّر | المهلة تُجهض المحاولة قبل أي إعادة؛ لا طلبان متزامنان على النموذج (`--timeout-ms`، افتراضيًا 120000 مع نموذج محلي) |
| حالة اتصال صادقة | انتهاء الجلسة أو توقف الـ Companion يظهر «انقطع الاتصال» ويعيد الواجهة إلى «غير مقترن»، لا «فشل المزوّد» |
| توفر صادق للنموذج | النموذج غير المثبت يظهر «النموذج غير مثبت» ولا يُحسب متاحًا (مطابقة اسم حرفية، بلا استبدال صامت) |

## 2. الفحص الحقيقي لـ Ollama (يولّد دليلًا)

```bash
node companion/cli.js probe --ollama-model qwen2.5:3b --smoke --evidence-out probe-evidence.json
```

| رمز الخروج | المعنى |
|---|---|
| 0 | الخدمة تستجيب والنموذج مثبت (ومع `--smoke`: عيّنة اصطناعية واحدة أعادت مخرجًا صالحًا للمخطط) |
| 3 | خدمة النموذج لا تستجيب على العنوان المحلي |
| 4 | الخدمة تستجيب لكن النموذج المطلوب غير مثبت (`ollama pull <NAME>`) |
| 5 | عيّنة الدخان لم تُنتج مخرجًا صالحًا للمخطط (لا يُعرض أي مخرج غير صالح كنتيجة) |

الملف الناتج `LocalProviderProbeEvidenceV1` يحتوي: نظام التشغيل والمعمارية وإصدار Node (بلا اسم جهاز أو مستخدم)،
حالة الخدمة، النماذج المثبتة، وتصنيفًا ثابتًا:

```
MODEL_AVAILABLE  = true|false        ← ما رآه الفحص فقط
MODEL_EVALUATED  = false             ← لا تقييم على مجموعة مقبولة
MODEL_ADMITTED   = false             ← لا اعتماد لأي مهمة
PRODUCTION_READY = false
```

عيّنة الدخان (`--smoke`) حمولة **اصطناعية ثابتة** (لا بيانات مستخدم)، حجمها 1، وتثبت أن مسار النقل والمخرجات المهيكلة
يعمل على هذا الجهاز؛ ولا تقول شيئًا عن جودة التوصية.

## 3. ما بقي غير مثبت (NOT_PROVEN) وكيف يُغلق

| البند | لماذا لم يُثبت هنا | الإغلاق |
|---|---|---|
| Ollama حقيقي | لا Ollama في بيئة البناء؛ نطاقات النماذج وDocker Hub محجوبة؛ القناة إلى الجهاز المحلي غير متاحة | تشغيل §2 على الجهاز وحفظ `probe-evidence.json` |
| Windows الأصلي | لا بيئة Windows | تشغيل §1 و§2 على Windows، ولقطة لحالة الاتصال |
| مخزن أسرار النظام | `secret-tool` غير مثبت ولا يمكن تثبيته (المستودعات محجوبة)؛ Windows يفشل مغلقًا عمدًا | غير مطلوب للنموذج المحلي؛ يُفتح فقط بقرار مزوّد مستضاف |
| مزوّد مستضاف حقيقي | الاستدعاءات المدفوعة غير مصرّح بها | تفويض منفصل + ميزانية معتمدة |
| أداء النموذج | لا مجموعة تقييم مقبولة (`EVALUATION_CORPUS = REVIEW_PENDING`) | مراجعة بشرية للمجموعة ثم تشغيل التقييم |
